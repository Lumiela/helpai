# 매뉴얼 04. 문제 해결

증상 → 원인 → 할 일. 위에서부터 흔한 순.

---

## 집 PC — 환경

| 증상 | 원인 | 할 일 |
|---|---|---|
| `torch.cuda.is_available()` False | WSL 이 GPU 를 못 봄 / CPU 판 torch | Windows 드라이버 최신 → `wsl --shutdown` 후 다시 → WSL `nvidia-smi`. torch 는 cu128 판으로 다시 설치 |
| `no kernel image is available for execution on the device` / `sm_120 is not compatible` | RTX 50 계열인데 cu121·cu124 판 torch | `pip install --force-reinstall torch --index-url https://download.pytorch.org/whl/cu128` |
| `pip install -r requirements-train.txt` 후 위 증상 | laya 의존성이 torch 를 PyPI 판으로 바꿈 | 위와 같음, 그다음 check-env |
| `laya` 설치 실패 `Requires-Python >=3.10` | 파이썬이 낮음 | Ubuntu 24.04(3.12) 사용 |
| `laya.load()` 가 멈춤 | TensorFlow 가 같이 깔려 있음 | `export USE_TF=0` |
| 한글이 `???` 로 깨짐 (Windows 에서 직접 돌릴 때) | 콘솔 코드페이지 | `set PYTHONUTF8=1` (PowerShell: `$env:PYTHONUTF8=1`). WSL 에서는 문제 없음 |

## 집 PC — 학습

| 증상 | 원인 | 할 일 |
|---|---|---|
| check-env 에 `laya.train.finetune … 없음` / `TrainConfig 없음` | laya 판이 바뀌어 학습 API 이름이 다름 | ① `pip install laya==0.5.5` 로 고정 판 사용 ② 새 판을 써야 하면 check-env 출력의 실제 이름에 맞춰 `helpai_decide/laya_tools.py` 의 `train()` 만 고친다 |
| `finetune… 의 필수 인자 [...] 를 모른다` | 인자 이름 변경 | 같은 파일 `args = {...}` 에 이름 추가 |
| `TrainConfig 에 없는 설정은 무시: …` 경고 | 설정 이름 변경 | 경고에 나온 키를 `configs/training.yaml` 에서 새 이름으로 |
| `CUDA out of memory` | 배치가 큼 | `micro_batch: 4` → `gradient_checkpointing: true` → `micro_batch: 2` |
| 학습 데이터 행이 많이 `skipped` (`invalid_target`, `options_collapsed`) | gold 의 키가 질문 선택지와 다름 | `dataset check` 로 확인. 질문을 바꿨으면 데이터셋부터 다시 |
| 손실이 내려가지 않음 | 학습률·손실 | `loss: soft-ce` 비교, `encoder_lr: 1.25e-5` |
| 정확도는 높은데 ECE 가 큼 | 과신 | calibrate 가 고친다. 그래도 크면 경계 데이터(`edge_frac`) 늘리기 |

## 집 PC — ONNX·평가

| 증상 | 원인 | 할 일 |
|---|---|---|
| export 에서 `ModuleNotFoundError: rl_common` | 체크포인트 폴더에 `rl_common.py` 없음 | `cp models/base/rl_common.py runs/$REV/model/` (키트가 자동으로 하지만 기반 폴더에도 없으면 HF 저장소에서 직접) |
| export 에서 연산(op) 오류 | 내보내기 스크립트·torch 판 차이 | `git -C ~/src/laya-onnx log -1` 확인, 저장소 README 의 권장 판(torch·onnxscript)으로 맞춤 |
| `quant_pre_process` 경고 후 진행 | 큰 모델 shape 추론 실패 | 경고만이면 무시. INT8 결과는 9 단계 compare 로 판단 |
| compare 일치율 < 0.97 | INT8 손실 | FP16 묶음으로 |
| edge 서버 `적재 실패: 묶음 검사 실패: SHA256SUMS 없음` | 묶음이 아닌 폴더를 그냥 띄움 | 집 PC 비교 시험은 `LAYA_ALLOW_UNBUNDLED=1` |
| predict `실패가 너무 많다` | 서버 미준비 / 키 | `curl 127.0.0.1:810x/health`, 서버 로그. 키를 켰으면 `export LAYA_API_KEY=…` |
| `Cannot find module 'onnxruntime-node'` | edge 에서 npm install 안 함 | `cd edge && npm install` |

## 젯슨

| 증상 | 원인 | 할 일 |
|---|---|---|
| `docker logs laya-edge` 에 `묶음 검사 실패: 해시 불일치` | 전송 중 손상 / 풀린 뒤 수정 | tar 다시 받기, `sha256sum -c SHA256SUMS` |
| `파일 없음: …` 이 SHA256SUMS 모든 줄에 | 줄바꿈 CRLF 묶음(옛 키트) | 지금 키트는 LF 고정. 묶음을 다시 만든다 |
| `ENOENT … /models/current` | current 링크가 절대경로(호스트 경로)를 가리킴 | `cd /data/laya/models && sudo ln -sfn <rev> current` (상대 링크) |
| 컨테이너가 계속 재시작 (`OOMKilled`) | 메모리 | `docker inspect laya-edge --format '{{.State.OOMKilled}}'`. Grafana 잠시 끄고 재측정, INT8 인지 확인 |
| bench 가 너무 느림 | CPU 경합 | `LAYA_THREADS` 조정(3↔4), rules 주기 늘림, 질문 수 줄임 |
| `npm install` 이 빌드 중 실패 (arm64) | onnxruntime-node arm64 바이너리 문제 | `docker build` 출력 저장. 대안: Python 3.8 + Jetson Zoo onnxruntime 경로(docs/01 §3-1 B) |
| rules 에서 `laya-edge` 이름을 못 찾음 | compose 망이 다름 | 두 서비스가 같은 `/data/edge/docker-compose.yml` 안에 있는지 |
| `influx query 401` / `404` | 읽기 토큰 / 경로 | 토큰 다시 확인. URL 은 `…/influx/api/v2/query` (창구 허용 목록) |
| `export LAYA_API_KEY` 가 compose 에서 비었다는 오류 | `/data/edge/.env` 없음 | 매뉴얼 03 §1 |

## 그래도 안 되면

출력 전체(`check-env`, 실패한 명령의 마지막 50 줄, `docker logs --tail 100 laya-edge`)를 `reports/<rev>/issue.txt` 로 저장해 커밋해 두면,
학교에서 같은 상태를 보고 이어서 고칠 수 있다. 토큰·키가 출력에 섞이지 않았는지 먼저 확인한다.
