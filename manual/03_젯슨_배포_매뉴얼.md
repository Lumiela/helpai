# 매뉴얼 03. 젯슨 배포 (Xavier NX 8 GB — shadow 수집기 + 추론)

젯슨에서 두 가지를 돌린다. **서버(네이버 클라우드, `backend` 브랜치)는 건드리지 않는다.**

| 서비스 | 하는 일 | 필요한 것 | 언제 |
|---|---|---|---|
| `collector` (shadow 수집기) | 1 분마다 서버를 **읽기만** 하고 기준 판단(autoctl 규칙)·autoctl 실제 상태·(있으면) 모델 답을 기록. **명령 없음** | 서버 인스턴스 ID, 소유자 계정 refresh token | **지금 바로** (모델 없이도 기록) |
| `laya-edge` | 묶음(ONNX INT8)으로 추론 | 집에서 만든 `bundles/<rev>.tar` | 학습 1회차 뒤 |

두 서비스 모두 이 브랜치의 `edge/docker-compose.yml` 로 띄운다(젯슨 전용, 서버 compose 와 별개).

## 2. 처음 한 번 — 수집기 계정과 토큰

서버 api 는 **Supabase 로그인 토큰**만 받고, 그 **인스턴스의 소유자** 계정이어야 values·status·auto·history 를 읽을 수 있다(별도 서비스 토큰 없음).

1. **계정**: 수집기 전용 계정을 권장한다(사람 로그인과 세션이 섞이지 않게). 그 계정을 인스턴스 소유자로 넣는 것은 서버 담당이 한다.
   전용 계정이 없으면 기존 소유자 계정을 써도 되지만, 아래 3 처럼 **별도 세션**을 만든다.
2. **값 모으기** (화면·커밋에 남기지 말 것):
   - 인스턴스 ID — 웹 주소 `/i/<인스턴스 ID>/` 의 값
   - `SUPABASE_URL`(`https://<ref>.supabase.co`) · `SUPABASE_ANON_KEY`(웹 화면이 쓰는 공개 anon 키) — 서버 담당 또는 웹 설정
3. **refresh token 받기** — 젯슨 셸에서 직접(암호는 화면에 안 보이게):
   ```bash
   read -r  SUPABASE_URL; read -rs SUPABASE_ANON_KEY; read -r EMAIL; read -rs PASS
   curl -s -X POST "$SUPABASE_URL/auth/v1/token?grant_type=password" \
     -H "apikey: $SUPABASE_ANON_KEY" -H "Content-Type: application/json" \
     -d "{\"email\":\"$EMAIL\",\"password\":\"$PASS\"}" \
     | python3 -c "import sys,json; d=json.load(sys.stdin); print(d.get('refresh_token') or d)" \
     | sudo tee /data/collector/state/refresh_token > /dev/null
   unset PASS
   sudo chown 65534:65534 /data/collector/state/refresh_token && sudo chmod 600 /data/collector/state/refresh_token
   sudo head -c 6 /data/collector/state/refresh_token; echo '…'     # 앞 몇 글자만 확인 (오류 JSON 이면 다시)
   ```
   - refresh token 은 **1 회용**이다. 수집기가 쓸 때마다 새 것으로 바뀌어 같은 파일에 저장된다 → 이 파일을 다른 곳에서 쓰지 않는다.
   - 수집기가 오래 꺼져 있었거나 세션이 끊기면 `토큰 갱신 실패 HTTP 400` — 이 3 단계를 다시 한다.
4. **`edge/.env`** (git 무시 대상):
   ```bash
   cd ~/helpai-decision/edge
   umask 077
   {
     echo "COLLECTOR_INSTANCE=<인스턴스 ID>"
     echo "COLLECTOR_CUBES=CUBE001"
     echo "SUPABASE_URL=$SUPABASE_URL"
     echo "SUPABASE_ANON_KEY=$SUPABASE_ANON_KEY"
     echo "LAYA_API_KEY=$(openssl rand -hex 24)"
     echo "COLLECTOR_LAYA=0"
   } > .env
   ```
   (refresh token 은 3 에서 파일로 넣었으므로 `.env` 에 넣지 않아도 된다.)

## 3. 수집기 띄우기 (모델 없이 — 지금 바로)

```bash
cd ~/helpai-decision/edge
docker compose up -d --build collector
docker logs -f collector
```
정상이면 1 분마다:
```
[shadow] CUBE001 fan_action=hold light_action=increase irrigate_now=false plant_stress=mild data_suspect=false | model laya 꺼짐
```
- `skip: values 없음` + `errors values` → 인스턴스 ID·토큰·큐브 SN 확인 (매뉴얼 04)
- 기록: `/data/collector/logs/shadow-YYYY-MM-DD.jsonl` (KST 날짜, 1 분에 큐브당 한 줄)

한 번만 돌려 보기(설정 확인용):
```bash
docker compose run --rm collector python -m helpai_decide collect --config /app/configs/collector.yaml --once --no-model
```

## 4. 묶음 올리기 (학습 1회차 뒤)

집 PC 에서 (또는 USB):
```bash
scp bundles/2026-12-05_r1.tar <젯슨 계정>@<젯슨>:/data/laya/incoming/
```
젯슨에서:
```bash
cd /data/laya/models
sudo tar -xf /data/laya/incoming/2026-12-05_r1.tar          # → 2026-12-05_r1/
(cd 2026-12-05_r1 && sha256sum -c --quiet SHA256SUMS && echo 해시 OK)
head -30 2026-12-05_r1/manifest.json
sudo ln -sfn 2026-12-05_r1 current                             # ★ 상대 링크
```

## 5. laya-edge 띄우고 수집기에 연결

```bash
cd ~/helpai-decision/edge
docker compose --profile model up -d --build laya-edge
docker logs -f laya-edge                                        # "적재 2026-12-05_r1 …" 이면 준비
sed -i 's/^COLLECTOR_LAYA=0/COLLECTOR_LAYA=1/' .env
docker compose up -d collector                                  # 다시 만들어 모델 답도 기록
```
교체(새 묶음):
```bash
sudo ln -sfn 2026-12-05_r2 /data/laya/models/current
set -a; . ~/helpai-decision/edge/.env; set +a
curl -s -X POST -H "Authorization: Bearer $LAYA_API_KEY" http://127.0.0.1:8000/admin/reload; echo
```
`{"ok":true,…}` 면 완료. 깨진 묶음이면 `{"ok":false,…,"kept":"…"}` — 이전 모델로 계속.

## 6. 실측 (laya-edge)

```bash
docker exec laya-edge node bench.mjs --n 20
curl -s http://127.0.0.1:8000/health; echo
docker stats --no-stream; free -h
```

| 항목 | 기준 | 못 넘으면 |
|---|---|---|
| bench p95 (질문 5 개) | < 8 s | `LAYA_THREADS` 4 · 수집 주기 120 s(`configs/collector.yaml` every_s) · 질문 줄이기 |
| laya-edge 메모리 | < 1.5 GB | 다른 컨테이너 정리 후 재측정 |
| 젯슨 available | ≥ 1 GB | 위와 같음 |

결과는 `reports/<rev>/jetson_bench.txt` 로 커밋.

## 7. shadow 기록 보기

```bash
docker compose run --rm collector python -m helpai_decide shadow-report --logs '/data/collector/logs/shadow-*.jsonl'
```
질문별 `agree_with_baseline`(모델 ↔ autoctl 기준 판단 일치율)·`mean_confidence`, 오류 수, 지연. 이 수치가 단계 4·5 로 갈지 판단하는 근거다(docs/06 §5).
2회차 학습 때는 기록 파일을 집 PC `data/shadow/` 로 복사하고 `configs/dataset.yaml` 의 `shadow.enabled: true`.

## 8. 되돌리기 · 끄기

```bash
sudo ln -sfn <이전 revision> /data/laya/models/current      # 그다음 5 의 reload
cd ~/helpai-decision/edge && docker compose --profile model stop laya-edge    # 모델만 끄기 (수집기는 계속)
docker compose stop collector                                                 # 수집기 끄기
```
수집기·laya-edge 를 꺼도 큐브 제어(서버 autoctl)에는 아무 영향이 없다 — 처음부터 읽기만 했기 때문이다.

## 9. 정리 규칙

- `/data/laya/models/` 에는 지금 것 + 직전 것 2 개만. 지우기 전에 `ls -l current`.
- `/data/collector/logs/` 는 하루 수 MB 수준. 학습에 복사한 날은 압축 보관(`gzip`)해도 된다.
- `/data/collector/state/refresh_token` 은 백업·복사하지 않는다(1 회용, 복사본은 곧 무효).
