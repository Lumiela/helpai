# 매뉴얼 03. 젯슨 배포 (Xavier NX 8 GB — 현장 엣지, 추론만)

집에서 만든 `bundles/<rev>.tar` 를 젯슨 `laya-edge` 컨테이너로 올리고, 지연·메모리를 잰 뒤 교체한다.
**서버(네이버 클라우드, `backend` 브랜치)는 건드리지 않는다.** 젯슨에는 젯슨 전용 compose(`/data/edge/docker-compose.yml`)를 둔다.

---

## 0. 처음 한 번 — 젯슨 상태 확인

```bash
cat /etc/nv_tegra_release        # R35.x = JetPack 5.1.x
free -h                          # available 이 2 GB 이상이면 시작
docker ps --format '{{.Names}}'  # 서버가 클라우드로 옮긴 뒤 젯슨에 무엇이 남아 있는지
docker stats --no-stream
curl -sI https://smartcubens.duckdns.org/influx/ping | head -1     # 서버 InfluxDB 창구까지 나가지는지 (204 기대)
```
옛 서버 컨테이너(api·influxdb·grafana 등)가 아직 젯슨에서 돌고 있으면, 그것을 끌지는 팀과 정한다 — 끄면 메모리 여유가 크게 는다.

## 1. 처음 한 번 — laya-edge 설치

```bash
git clone -b decision_model https://github.com/Lumiela/helpai.git ~/helpai-decision
sudo mkdir -p /data/edge /data/laya/models /data/laya/incoming
sudo cp ~/helpai-decision/edge/{package.json,server.mjs,bench.mjs,sample_request.json,Dockerfile,docker-compose.yml} /data/edge/
[ -f ~/helpai-decision/edge/package-lock.json ] && sudo cp ~/helpai-decision/edge/package-lock.json /data/edge/
```

추론 서버 키 (임의의 긴 문자열, 화면·커밋에 남기지 말 것):
```bash
echo "LAYA_API_KEY=$(openssl rand -hex 24)" | sudo tee /data/edge/.env > /dev/null
sudo chmod 600 /data/edge/.env
```
(나중에 rules 컨테이너도 같은 compose 에 넣고 같은 `LAYA_API_KEY` 를 쓴다.)

## 2. 묶음 올리기

집 PC 에서 (또는 USB):
```bash
scp bundles/2026-12-05_r1.tar <젯슨 계정>@<젯슨>:/data/laya/incoming/
```
젯슨에서:
```bash
cd /data/laya/models
sudo tar -xf /data/laya/incoming/2026-12-05_r1.tar          # → 2026-12-05_r1/
(cd 2026-12-05_r1 && sha256sum -c --quiet SHA256SUMS && echo 해시 OK)
head -30 2026-12-05_r1/manifest.json                          # revision·precision·eval 확인
sudo ln -sfn 2026-12-05_r1 current                             # ★ 상대 링크 (컨테이너 안 /models/current 에서도 맞게)
ls -l current
```

## 3. 띄우기 (처음) / 다시 적재 (교체)

처음:
```bash
cd /data/edge && sudo docker compose up -d --build
docker logs -f laya-edge          # "적재 2026-12-05_r1 from /models/2026-12-05_r1 (… ms)" 가 나오면 준비
```
교체 (컨테이너는 그대로, 링크만 바꾸고):
```bash
sudo ln -sfn 2026-12-05_r2 /data/laya/models/current
set -a; . /data/edge/.env; set +a
curl -s -X POST -H "Authorization: Bearer $LAYA_API_KEY" http://127.0.0.1:8000/admin/reload; echo
```
`{"ok":true,"revision":"2026-12-05_r2"}` 면 교체 완료. 묶음이 깨졌으면 `{"ok":false,…,"kept":"2026-12-05_r1"}` — 이전 모델로 계속 돈다.

## 4. 실측 (단계 1 통과 기준)

```bash
docker exec laya-edge node bench.mjs --n 20
curl -s http://127.0.0.1:8000/health; echo
docker stats --no-stream
free -h
```

| 항목 | 기준 | 못 넘으면 |
|---|---|---|
| bench p95 (질문 5 개) | < 8 s | `LAYA_THREADS` 4 로 · rules 주기 120 s · 경보 질문 2 개만 |
| laya-edge 메모리 | < 1.5 GB (`mem_limit`) | OOM 재시작이 반복되면 다른 컨테이너 정리 후 재측정 |
| 젯슨 available | ≥ 1 GB | 위와 같음 |

결과는 `reports/<rev>/jetson_bench.txt` 로 적어 커밋해 둔다.

## 5. 서버와 연결 확인 (rules 연결 전 수동 점검)

rules 가 쓸 두 경로가 젯슨에서 열리는지 (토큰은 환경변수로만):
```bash
read -rs INFLUX_READ_TOKEN && export INFLUX_READ_TOKEN
curl -s -o /dev/null -w "influx query %{http_code}\n" -X POST https://smartcubens.duckdns.org/influx/api/v2/query?org=smartcube \
  -H "Authorization: Token $INFLUX_READ_TOKEN" -H "Content-Type: application/vnd.flux" \
  --data 'from(bucket:"sensors") |> range(start:-5m) |> limit(n:1)'
curl -s -o /dev/null -w "api health %{http_code}\n" https://smartcubens.duckdns.org/api/health
```
`influx query 200`, `api health 200` 이면 된다. PolicyGate·shadow 기록 연결은 docs/01 §12 의 다음 단계 작업이다.

## 6. 되돌리기 · 끄기

```bash
sudo ln -sfn <이전 revision> /data/laya/models/current      # 그다음 3 의 reload
cd /data/edge && sudo docker compose stop laya-edge          # 모두 끄기 — rules 는 모델 없이 규칙만으로 계속
```

## 7. 정리 규칙

- `/data/laya/models/` 에는 **지금 것 + 직전 것 2 개**만 남긴다(NVMe 여유). 지우기 전에 `ls -l current` 로 링크 대상 확인.
- `/data/laya/incoming/*.tar` 는 풀고 해시 확인 후 지운다.
