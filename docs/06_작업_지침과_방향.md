# 06. 작업 지침과 방향 — 다른 환경에서 이어 가기

작성 2026-11-27. **이 문서 하나로 어느 환경(집 PC · 학교 노트북 · 젯슨 · 새 Claude Code 세션)에서든 지금 상태를 파악하고 다음 일을 시작할 수 있게** 한다.
진행할 때마다 §2 상태표와 §8 결정 기록을 고친다(커밋과 같이).

## 1. 이 작업이 향하는 곳 (방향)

**목표**: 서버 InfluxDB 의 센서 이력으로 결정 모델 **Laya** 를 학습시켜, 현장 젯슨에서 **추론만** 하고,
지금 서버에서 큐브를 제어하는 **autoctl** 옆에서 "두 번째 판단"을 낸다 — 처음엔 기록(shadow)만, 검증되면 경보, 그다음 제어 보조.

**원칙 (바꾸지 않는다)**
1. **서버(backend 브랜치)는 고치지 않는다.** 읽기(InfluxDB 조회 창구, api 조회)만 한다. 서버를 바꿔야 하는 일은 팀 결정 + backend 브랜치에서.
2. **큐브에 명령을 보내는 코드는 PolicyGate 단계 전까지 만들지 않는다.** autoctl 이 켜진 큐브에 명령을 보내면 사람 조작으로 처리돼 autoctl 이 꺼진다(05 §7).
3. **모델은 판단(라벨)만, 명령·안전은 결정론 코드.** 안전 봉투(급수 하루 4 회·60 분·보정 안 된 센서 급수 금지·야간 LED 0)는 항상 코드가 이긴다.
4. **학습 정답 = autoctl 규칙**(지금 실제로 도는 제어). autoctl 이 바뀌면 라벨도 바꾼다. 규칙보다 나아지는 건 사람 정정·결과 지표를 더하는 2 회차부터.
5. **학습과 추론은 같은 코드로 state·질문을 만든다**(`features.py`·`questions.yaml`). 바꾸면 버전을 올리고 데이터셋부터 다시.
6. **비밀은 저장소 밖.** 토큰·키는 환경변수 또는 그 장비의 `.env`(git 무시)에만.
7. **큰 파일은 git 밖.** 모델·데이터·묶음은 scp/USB. git 에는 코드·문서·작은 보고서(`reports/<rev>/`)만.

### 5-1. 단계 1 에서 처음 확인될 것 (위험 순)
1. `check-env` 의 laya 학습 API 이름이 `laya_tools.train` 과 맞는지 (laya 0.5.5 기준으로 짰다).
2. receptron `export_onnx.py` 가 **미세조정한** 체크포인트를 내보내는지 (`rl_common.py` 필요).
3. `@receptron/laya` 0.2.0 이 우리 묶음(INT8)을 읽는지, 결과 필드(`confidence`/`answer_confidence`)가 `predict.normalize_answer` 와 맞는지.
4. 학습 시간·메모리 실측.
→ 막히면 [manual/04](../manual/04_문제해결.md). 해결한 내용은 manual/04 에 한 줄 더한다.

### 5-2. 단계 1 결과를 판단하는 법
- 1회차는 합성 위주라 "autoctl 을 확률로 흉내" 내는 모델이다. 목표는 **파이프라인 완주와 젯슨 실측**이지 점수가 아니다.
- `eval_report.json` 의 `confusion` 에서 **위험한 오답**(irrigate true↔false, fan up↔off, stress severe→none)을 먼저 본다.

### 5-3. shadow 수집기 (단계 3 — 코드 완료, `helpai_decide/collector.py`)
- 실행: `edge/docker-compose.yml` 의 `collector` 서비스(이미지 `collector/Dockerfile`, pyyaml 만), 명령 `python -m helpai_decide collect`.
- 입력: 서버 api `GET /i/{iid}/cubes/{sn}/values`·`status`·`auto`·`history` — 추세·급수 이력도 api `history` 로 받아 **InfluxDB 토큰이 필요 없다**.
  급수 횟수·마지막 급수는 autoctl 상태(`pump_count`·`pump_last_at`)를 우선, 없으면 오늘 펌프 이력에서 센다.
- 인증: 서버에 서비스 토큰이 없어 **소유자 계정의 Supabase refresh token** 으로 access token 을 스스로 갱신(1 회용 → 새 것을 `/data/collector/state` 에 저장).
  - 조회 라우트(`auth.reader`)는 **운영자 읽기 접근**도 받지만 쓰지 않는다: 마스터 키 + 사유로 발급, 60 분 수명, api 메모리에만 있어 재시작하면 사라진다 — 사람의 점검용이다.
  - 소유자 계정은 서버에서 제어도 할 수 있는 권한이다. **수집기가 읽기만 한다는 보장은 서버가 아니라 수집기 코드(`ApiClient`)가 한다** → 이 토큰 파일을 다른 도구에 쓰지 않는다.
- 처리: `build_snapshot` → `features.build_state` → (COLLECTOR_LAYA=1 이면) laya-edge `/v1/systemone` → 묶음 `calibration.yaml` 온도 적용, manifest 의 질문 해시·특징 판 대조.
- 기록: `/data/collector/logs/shadow-YYYY-MM-DD.jsonl` (KST 날짜, 큐브당 1 분에 한 줄)
  - 공통: `t`·`sn`·`iid`·`feature_version`·`questions_sha256`·`errors`(실패한 조회)
  - values 를 못 받으면 `skipped: "values 없음"` 으로 끝(나머지 없음)
  - 그 외: `snapshot`·`state`·`baseline`(`labeler.HARD`)·`autoctl`(enabled·crop_id·phase·rules·alerts·paused·last_eval·last_action·pump_count)·`model`(revision·mismatch·latency_ms·raw·calibrated·top·confidence, 또는 error/꺼짐)
- 요약 `shadow-report`: records·skipped·autoctl_enabled 수·조회별 오류 수·지연 p50/p95·질문별 `agree_with_baseline`·`mean_confidence`. 일치율은 모델 답이 있는 줄만 센다(3a 에서는 비어 있다).
- 2회차 학습: `configs/dataset.yaml` 의 `shadow` 출처 — 기록의 `snapshot` 을 다시 읽어 같은 교사로 정답을 매긴다.
- **명령을 보내는 기능은 없다**: `ApiClient` 는 GET 만, 경로 끝은 values·status·auto·history 만 허용(시험으로 고정).

**알려진 한계 (실서버에서 확인할 것)**

| 항목 | 내용 | 영향 |
|---|---|---|
| autoctl 상태는 api 메모리 | api 가 다시 시작되면 `auto.state` 가 비거나 `pump_count` 0 | `pump_last_at` 이 없으면 오늘 펌프 이력으로 대신 센다 |
| 펌프 이력 대신 세기 | history `every=1m` 평균에서 0→양수 전환을 센다(구간은 오늘 0 시부터, 최소 61 분 — 자정 넘는 대기용). 5 초 펄스가 data 보고 사이에 끝나면 안 보일 수 있다 | 급수 횟수 과소 — autoctl 상태가 있으면 쓰지 않는 경로 |
| history 는 서버의 Influx 토큰 필요 | 서버에 `INFLUX_READ_TOKEN` 이 없으면 503 | 추세·평탄 값 None, `errors.history` 로 기록. 판단은 계속 |

## 6. 작업 규칙 (코드·문서·커밋)

**바꿀 때 규칙**

| 바꾸는 것 | 함께 할 일 |
|---|---|
| state 문장 (`features.py`) | `FEATURE_VERSION` + 1, `tests/test_core.py` 수정, docs/04 §2 |
| 질문 (`configs/questions.yaml`) | `version` + 1, docs/04 §3, docs/01 §9 |
| 교사 규칙 (`labeler.py`) | 먼저 시험을 고치고 코드, docs/04 §3·docs/05 §8 |
| 서버 autoctl·crops.json 이 바뀜 | `profiles/crops.json` 다시 복사(출처 커밋 적기) → features 상수·labeler → 시험 → docs/05 |
| 위 어느 것이든 | **데이터셋부터 다시**, 재학습. 이전 묶음은 젯슨에서 자동 shadow |

**문서**: 한국어, 표 위주, "확인한 것 / 못 한 것"을 구분해 적는다. 수치는 출처(실측/공개 자료)를 밝힌다. 코드와 다르면 코드가 맞고 문서를 고친다.

**커밋**: 제목 한 줄(무엇을) + 본문(왜·영향). 시험이 통과한 상태로만 커밋. Claude 가 만든 커밋은 끝에 `Co-Authored-By` 줄.
푸시는 `decision_model` 브랜치에만. 비밀·큰 파일이 섞이지 않았는지 `git status` 로 확인.

**하지 말 것**
- backend·Hardware·main 브랜치에 커밋
- 서버 api 제어 라우트·MQTT 로 명령 보내기 (단계 6 전)
- 토큰을 명령줄 인자·파일·커밋에 남기기 (`read -rs` 로 환경변수에)
