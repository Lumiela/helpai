# 05. 현재 제어 방식 — 서버 api 의 autoctl 기준

작성 2026-11-27. 근거는 저장소 [Lumiela/helpai](https://github.com/Lumiela/helpai) 의 두 브랜치다:
- `backend` 브랜치 `28aed59` (2026-11-13) — `api/app/autoctl.py`, `api/app/crops.py`·`crops.json`, `api/app/main.py`
- `Hardware` 브랜치 `611b2d7` (2026-10-26) — `esp32_devkit_node/` (`FW_VERSION "cube-devkit-1.2.3"`)

**코드와 이 문서가 다르면 코드가 맞다.** 이 브랜치(decision_model)의 교사 라벨(`helpai_decide/labeler.py`)은 이 문서의 autoctl 규칙을 따른다.

## 1. 한 장 요약

```
 사람(웹 화면) ──POST /i/{iid}/cubes/{sn}/control (소유자 인증)──┐
                    │ _manual_override: 그 큐브 autoctl 끔         │
                    ▼                                             ▼
 autoctl (api 안, 10 s 마다) ── _auto_send(require_auto) ──▶ _send_control  ← 둘이 같은 송신 함수·같은 잠금·같은 seq
                                                                  │  {session, seq+1, pump, led1, led2, fan1, fan2}
                                                                  ▼  agframe 인코딩
                                          MQTT  device/<AG_APP>/<SN>/notify/control  (qos 0)
                                                                  ▼
 ESP32 (cube-devkit-1.2.3): 프레임·세션·순번 검사 → applyControl → ack(result)  ── 5 s 안에 안 오면 api 504
                                                                  ▼
                                    펌웨어 안전장치: 펌프 최대 30 s 연속 가동 후 자동 정지
```

- 제어 주체는 **사람**과 **autoctl** 두 가지다. 사람이 한 번이라도 조작하면 그 큐브의 autoctl 이 꺼지고, 사용자가 다시 켤 때까지 꺼져 있다.
- 로컬 `rule - based v2`(규칙 엔진)는 저장소에 없고 기본값이 dry-run 이다. **지금 운영 제어로 보지 않는다.**

## 2. 송신 경로 (`main.py`)

| 단계 | 내용 |
|---|---|
| 라우트 | `POST /i/{iid}/cubes/{sn}/control` — 소유자 인증(`auth.owner`). 본문 `pump`·`led1`·`led2`·`fan1`·`fan2`, 모두 선택(0~100, pump 는 bool) |
| 사람 조작 처리 | `_manual_override`: autoctl 이 켜져 있으면 메모리에서 즉시 끄고(`autoctl.note_manual`, 진행 중인 급수 펄스의 끄기도 사람에게 넘김) Supabase 저장은 기다리지 않음. audit `auto_off_manual` |
| `_send_control` | 브로커 미접속 → 503. 세션 모름(텔레메트리를 아직 못 받음) → 409. **빠진 키는 마지막 텔레메트리 값으로 채움.** `seq = last_seq + 1` 을 잠금 안에서 올림 |
| 자동 제어 송신 | `require_auto=True` — 보내기 직전에 autoctl 이 아직 켜져 있는지 다시 봄. 사람 조작으로 꺼졌으면 `skipped`(사람 명령을 덮어쓰지 않음) |
| 발행 | `device/<AG_APP>/<SN>/notify/control`, agframe 인코딩, qos 0 |
| 결과 | ack 를 `ACK_TIMEOUT`(기본 5 s) 동안 기다림. 없으면 504. 모든 송신은 audit 기록(주체: 사람 이메일 / `auto`) |

**의미:** 다른 프로그램(예: 젯슨)이 MQTT 로 직접 명령을 내면 seq 가 엇갈려 `duplicate_or_old_seq` 로 거절된다.
제어 라우트로 보내면 **사람 조작으로 처리되어 autoctl 이 꺼진다.** → §7.

## 3. 펌웨어 (`Hardware` 브랜치 `esp32_devkit_node`)

| 항목 | 값·동작 |
|---|---|
| 텔레메트리 | 5 s 마다 (`TELEMETRY_INTERVAL_MS 5000`) |
| 제어 검사 | comm 이 프레임·세션·순번을 검사한 뒤 `applyControl` → 반환값이 ack `result` |
| ack result | `ok` · `stale_session` · `duplicate_or_old_seq` · `bad_request` · `out_of_range` · `outputs_disabled`(진단 모드) · `pump_locked` · `denied`(없는 하드웨어 값을 바꾸려 함·모듈 fault) |
| 없는 하드웨어 | `fan2`(순환팬 핀 미배정)·`led2` 는 지금 값과 같을 때만 통과, 다르면 `denied` |
| 펌프 | `PUMP_MAX_MS 30000` — 30 s 넘게 켜져 있으면 자동 정지. `PUMP_COOLDOWN_MS 0` |
| 리스(연결 감시) | `LEASE_MS 15000` 이지만 **`LEASE_ENFORCED = false`** — 서버 연결이 끊겨도 아무것도 끄지 않는다(로그만). 펌프는 30 s 제한으로만 멈춘다 |
| 부팅 직후 배기팬 | `SAFE_FAN_PERCENT 100` (환기 유지) |

> ⚠ 이 브랜치의 이전 문서(01·02)에 "연결이 끊기면 펌프를 끈다"고 적었던 것은 **틀렸다** — 지금 펌웨어 설정으로는 끄지 않는다. 고쳤다.

## 5. autoctl 규칙 (`autoctl.py`)

큐브마다 10 s(`AUTO_INTERVAL_SECONDS`)에 한 번 `evaluate()`. **큐브 한 대의 값만 본다**(`temperature`·`humidity`·`moisture_pct`·`lux`·`fan1`·`led1`·`pump`).
주간/야간은 광주기로 정하고, 온도·습도 범위는 주야 따로(장미는 같음).

### 5-1. 판단하지 않는 경우
- 보고가 30 s(`STALE_S`) 넘게 없음 → 출력 유지, "센서 점검 필요"
- `diag_mode` → 판단 안 함

### 5-2. 배기팬 `fan1` — 단계 0 → 33 → 66 → 100 (위에서부터 처음 맞는 것)

| 조건 | 원하는 단계 |
|---|---|
| 온도 또는 습도 값 없음 | 지금 출력 유지 + "센서 점검 필요" |
| 온도 < 최저 | **0** (온도 낮음) |
| 온도 > 최고 | **한 단계 올림** (온도 높음) |
| 습도 > 최고 | **한 단계 올림** (습도 높음) |
| 습도 < 최저 | **0** (습도 낮음) |
| 지금 > 0 이고 온도 ≤ 최고 − 1 °C 이고 습도 ≤ 최고 − 5 %p | **한 단계 내림** (범위 안으로 돌아옴) |
| 그 밖 | 그대로 |

- 온도 조건이 습도 조건보다 먼저 → "온도와 습도가 반대면 온도 우선".
- 실행 조건: 장치가 앞 단계를 실제로 적용한 것을 본 뒤에만, 단계를 바꾼 뒤 120 s 동안은 다시 안 바꿈.
- 시작 단계 = 장치가 보고한 팬 값에 가장 가까운 단계.

### 5-3. LED `led1`

| 조건 | 동작 |
|---|---|
| 야간 | 0 |
| 야간 → 주간으로 바뀐 첫 판단 | 50 % |
| 주간 도중 시작·서버 재시작 | 장치가 보고한 밝기에서 이어서(모르면 50 %) |
| 조도 값 없음 | 밝기 그대로 + "센서 점검 필요" |
| 조도 < 최저 이고 LED < 100 | **+10 %** |
| 조도 > 최고 이고 LED > 0 | **−10 %** |
| 그 밖 | 그대로 |

앞 단계가 장치에 적용된 것을 본 뒤에만 다음 10 % 를 움직인다.

### 5-4. 급수 `pump` (자동 제어가 켜져 있으면 함께 동작)

| 조건 | 동작 |
|---|---|
| 장치 status 의 `air`·`water` 를 아직 모름 | 급수 안 함 |
| `air = 22520` 이고 `water = 11100` (공장 기본값 = 보정 안 됨) | 급수 안 함 |
| `ads1115_ok = false` 또는 토양 값 없음 | 급수 안 함 + "센서 점검 필요" |
| 토양 < 최저 이고 펌프 꺼짐 | 오늘 4 회 다 씀 → 안 함 · 마지막 급수 후 60 분 안 → 대기 · 그 밖 → **5 s 펄스** |

- 펄스 끄기는 5 s 뒤 따로 보낸다(센서 보고가 끊겨도). 두 번 실패하면 펌웨어 30 s 자동 정지에 맡긴다.
- 하루 횟수는 KST 날짜가 바뀌면 0.

### 5-5. 실패·기록
- 송신 결과가 `ok` 가 아니면 30 s 뒤 재시도, 연속 5 회 실패 → 그 큐브 자동 제어 일시 정지(다시 켜면 재개).
- 방금 보낸 값이 15 s 안에 텔레메트리에 안 나타나면 같은 값을 다시 보내지 않는다.
- audit 는 명령을 보낼 때만(주체 `auto`, 판단 근거 `rules`·`readings`·`ranges` 포함). 범위 이탈 시작·해제는 상태 조회(`GET /i/{iid}/cubes/{sn}/auto`)에만.

## 7. 결정 모델(젯슨)을 이 구조에 붙이는 방법

autoctl 이 켜진 큐브에 젯슨이 제어 라우트로 명령을 보내면 **사람 조작으로 처리돼 autoctl 이 꺼진다.** 그래서 단계를 나눈다.

| 단계 | 젯슨이 하는 일 | 서버 변경 |
|---|---|---|
| **shadow (지금 목표)** | 명령을 보내지 않는다. 서버 InfluxDB·`values`·`GET …/auto`(autoctl 의 rules·phase·last_action)를 읽고, 모델 답과 autoctl 판단을 나란히 기록 | 없음 |
| 경보 | `data_suspect`·`plant_stress` 만 화면·알림으로 (명령 없음) | 없음 |
| advisory·primary | 그 큐브의 autoctl 을 사용자가 끄고, 젯슨 제어기(autoctl 규칙 이식 + PolicyGate)가 제어 라우트로 명령. 사람이 조작하면 젯슨도 손을 뗀다(30 분) | 없음 (서비스 토큰만 필요). 운영 중 전환은 팀 결정 |

그래서 교사 라벨을 autoctl 규칙에 맞췄다. shadow 기간의 "모델 ↔ autoctl 일치율"이 그대로 승격 판단 지표가 된다.

## 8. 질문 ↔ autoctl 대응 (교사 라벨)

| 질문 | autoctl 의 어느 판단 | 교사 정답 |
|---|---|---|
| `fan_action` (off·down·hold·up) | 5-2 의 "원하는 단계" | 지금 단계와 비교: 0 으로 → off(이미 0 이면 hold), 한 단계 내림 → down, 올림 → up(이미 100 이면 hold), 그대로 → hold |
| `light_action` (off·decrease·hold·increase) | 5-3 | 야간 → off, ±10 → increase/decrease, 그 밖 → hold |
| `irrigate_now` (noul) | 5-4 의 "5 s 펄스" | 펄스를 시작할 조건이면 true |
| `plant_stress` (none·mild·moderate·severe) | autoctl 의 범위 이탈(excursion)을 단계로 | docs/04 §3-4 |
| `data_suspect` (noul) | autoctl 의 "센서 점검 필요" + 확장 | docs/04 §3-5 |

실행 시점 조건(앞 단계 적용 확인·120 s 유지·15 s 재전송 방지·주간 시작 50 %)은 **모델이 아니라 제어기 코드**가 맡는다 — 모델은 "지금 무엇을 원하는가"만 답한다.
