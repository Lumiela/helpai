# 02. 데이터 흐름 — 운영(추론) 흐름과 학습 흐름

작성 2026-11-27. 같은 코드(`helpai_decide.features`·`questions`)가 두 흐름 모두에서 state·질문을 만든다는 것이 핵심이다.

---

## 1. 운영 흐름 (젯슨, 10 초 tick · 모델은 60 초마다)

```
ESP32 CUBE001/002 (현장)
   │  MQTT TLS 8443 (5 s 주기 텔레메트리)
   ▼
━━━━━━━━━━━━━━━━━━ 서버: 네이버 클라우드 smartcubens.duckdns.org ━━━━━━━━━━━━━━━━━━
nginx(stream) ─▶ mosquitto ──▶ api ──writer──▶ InfluxDB  smartcube/sensors   (measurement=mqtt, tag cube·kind, 숫자 필드만 float)
                                │                    │
     nginx 443 /api/ · /i/<iid>/api/ (인증)          nginx 443 /influx/ (조회 전용)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━│━━━━━━━━━━━━━━━━━━━━│━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
               HTTPS GET values (지금 값·seen)     HTTPS Flux (30 분 추세·오늘 관수 횟수·관수 후 수분 변화)
                                ▼                    ▼
━━━━━━━━━━━━━━━━━━ 현장: 젯슨 Xavier NX ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
         ┌──────────── rules 컨테이너 ─────────────────────────────────────┐
         │ ① Snapshot 만들기      (지금 값 + Influx 맥락)                    │
         │ ② RuleEngine(v2)       기준 판단 demands_rules                   │
         │ ③ features.build_state → state (9 개 키, 영어 판정 문장)          │
         │ ④ POST laya-edge /v1/systemone {state, questions}  (60 s 마다)   │
         │ ⑤ calibration.apply_temperature (묶음의 calibration.yaml)        │
         │ ⑥ PolicyGate  확신 문턱 · 안전 봉투 · 모드(shadow/advisory/primary) │
         │ ⑦ Arbiter·Safety(v2) → 명령                                      │
         │ ⑧ 서버 api POST /i/{iid}/cubes/{sn}/control (seq 는 api 만 관리)   │
         │ ⑨ decisions-*.jsonl 기록 (state·모델 확률·채택 여부 → 다음 학습 재료) │
         └──────────────────────────────────────────────────────────────────┘
               │
               ▼
          ESP32 ack (ok / denied / pump_locked …)
```
※ ①③⑤⑥ 의 rules 연결은 다음 단계(01 §12). 지금 저장소에는 ③⑤ 의 코드와 ④ 의 서버가 있다.

### 1-1. 한 tick 의 시간 예산 (젯슨 CPU 가정)

| 단계 | 예상 | 비고 |
|---|---|---|
| 서버 api values 읽기 | ~0.2 s + 인터넷 왕복 | v2 실측(연결 재사용)은 젯슨 내부 기준 — 클라우드 왕복은 실측 필요 |
| 서버 Influx 조회 | ~0.1~0.5 s + 왕복 | 60 s 캐시 → 대부분 0 |
| 모델 호출 | **수백 ms~수 초 (실측 필요)** | 비동기·시간 초과 8 s. 늦으면 이번 tick 은 규칙만 |
| 명령 | ~0.2~5 s | ack 대기 (v2 그대로) |

### 1-2. 실패하면

| 어디서 | 결과 |
|---|---|
| laya-edge 응답 없음·5xx | 이번 판단은 규칙만. 화면 "모델 꺼짐". 호출 간격 점점 늘림 |
| 묶음 해시 불일치 | laya-edge 가 적재 거부 → 이전 묶음 계속 (`/admin/reload` 응답 500, `kept`) |
| 질문 해시·특징 판 불일치 | rules 가 모델 답을 기록만(shadow) |
| Influx 실패 | 추세 문장이 "trend unknown" 으로 — 모델은 현재값만 보고 판단 |

## 2. 학습 흐름 (집 PC)

```
서버 InfluxDB ──https://smartcubens.duckdns.org/influx (읽기 토큰)──▶ export-influx ──▶ data/raw/influx_*.csv  (1 분 평균, 열 = CUBE.field)
                                                   │
                                                   ▼
                          replay.py: 분마다 Snapshot (관수 횟수·경과·수분 변화·추세·고착·데이터 나이 계산)
                                                   │          synth.py: 경계·이상 시나리오 Snapshot (seed 고정)
                                                   ▼                      │
                          features.build_state ─▶ state  ◀────────────────┘
                          labeler.label        ─▶ gold (질문별 확률 분포, 경계 근처는 0.7/0.3)
                                                   │
                                                   ▼
                          dataset.py: 중복 제거·토큰 예산 → train/val/test.jsonl (+ .meta.jsonl, dataset_info.json)
                                                   │
                                                   ▼
             models/base (convaiinnovations/laya typed-decisions) ──▶ laya.train.finetune ──▶ runs/<rev>/model
                                                   │
                                                   ▼
                          export_onnx.py (receptron) ──▶ onnx_fp32 ──convert──▶ onnx_int8
                                                   │
                   edge/server.mjs ×2 (집 PC 에서 젯슨과 같은 런타임) ◀── predict (val·test)
                                                   │
                          compare(fp32↔INT8 ≥ 97 %) · calibrate(val) · evaluate(test, acc ≥ 0.9 · ECE ≤ 0.1)
                                                   │
                                                   ▼
                          bundle make/verify ──▶ bundles/<rev>/ + <rev>.tar ──scp──▶ 젯슨
```

### 2-1. 파일과 형식

| 파일 | 형식 | 만드는 곳 |
|---|---|---|
| `data/raw/*.csv` | `time,CUBE001.temperature,…` (UTC, 창 끝, 빈칸 = 데이터 없음) | `export-influx` |
| `data/dataset/{train,val,test}.jsonl` | `{"state", "questions", "gold"}` 한 줄 한 행 (laya.train 입력 그대로) | `dataset build` |
| `data/dataset/*.meta.jsonl` | `{"id", "source", "scenario", "snapshot", …}` 같은 줄 순서 | `dataset build` |
| `data/dataset/dataset_info.json` | 행 수·분포·feature_version·questions_sha256 | `dataset build` |
| `runs/<rev>/model/` | laya 체크포인트 (`model.safetensors`, `encoder/`, `tokenizer/`, `rl_agent_config.json`, `rl_common.py`) | `train` |
| `runs/<rev>/onnx_fp32/`, `onnx_int8/` | `laya.onnx`, `laya_config.json`, `tokenizer/` | `export-onnx`, `convert` |
| `runs/<rev>/pred_*.jsonl` | `{"id", "pred": {질문: {선택지: p}}, "gold", "latency_ms"}` | `predict` |
| `runs/<rev>/calibration.yaml` | `{temperatures: {질문: T}}` | `calibrate` |
| `runs/<rev>/eval_report.json` | 질문별 n·정확도·ECE·Brier·혼동표·합격 | `evaluate` |
| `bundles/<rev>/` | 01 §6 | `bundle make` |

### 2-2. 왜 집 PC 에서도 edge 서버로 평가하나

젯슨에서 실제로 도는 것은 **INT8 ONNX + receptron 런타임**이다. PyTorch 원본으로 잰 점수는 그것과 다를 수 있다.
그래서 평가·보정은 **젯슨과 같은 서버 코드(`edge/server.mjs`)로 INT8 묶음을 띄워서** 한다. 이렇게 잰 온도·점수가 묶음에 들어간다.

## 3. 시퀀스 — 모델 교체 (카나리)

```
사용자(집)            젯슨 셸                     laya-edge                 rules
   │ scp <rev>.tar ───▶│ tar -x → models/<rev>/     │                         │
   │                   │ bundle verify (sha256sum)  │                         │
   │                   │ ln -sfn <rev> current      │                         │
   │                   │ curl POST /admin/reload ──▶│ SHA256SUMS 검사·적재     │
   │                   │◀── {ok, revision}          │ (실패 시 이전 유지)       │
   │                   │                            │◀── 다음 tick 요청 ──────│ GET /model 로 해시 대조
   │                   │                            │                         │ shadow 24 h → 지표 비교
   │                   │ (나쁘면) ln -sfn <이전> current + reload             │
```
