## 1. 전략 한 장

| 회차 | 데이터 | 기대 | 목적 |
|---|---|---|---|
| **1회차 (지금)** | 합성 20,000 + (있으면) Influx 재생 | 교사(규칙) 판단을 잘 흉내 | 파이프라인 전 과정 검증, 젯슨 지연 실측, shadow 시작 |
| 2회차 | + shadow 기간 기록, 사람 정정 | 규칙과 다를 때 사람이 맞다고 한 쪽으로 | 규칙보다 나은 판단의 시작 |
| 3회차~ | + 결과 지표(범위 안 시간 비율)로 라벨 재조정 | 실제 재배 결과 개선 | advisory → primary 승격 |

1회차 모델은 **"규칙을 확률로 말하는 모델"** 이다. 그 자체로 쓸모가 있다:
① 경계에서 얼마나 애매한지 확률로 보여 주고, ② 센서 이상(`data_suspect`)을 규칙보다 넓게 일반화하며,
③ 2회차부터 사람 정정을 받아들일 그릇이 된다.

## 2. 데이터

### 2-1. 합성 (`synth.py`)

| 항목 | 방법 | 이유 |
|---|---|---|
값은 모두 autoctl 판단(docs/05 §5)이 바뀌는 경계 기준이다 (장미 crops.json).

| 항목 | 방법 | 이유 |
|---|---|---|
| 시각 | 1년 전체, 주간 80 % / 야간 20 % (실제 야간은 23~01 시 2 시간뿐이라 일부러 늘림) | 야간 LED off 를 충분히 보게 |
| 온도 | 60 % 를 경계(22 · 30 · 29(최고−1) · 19 · 33 °C) ± 0.5, 나머지 12~42 균등 | 팬 off/up/down·스트레스 경계 |
| 습도 | 60 % 를 경계(60 · 70 · 65(최고−5)) ± 1.5, 나머지 20~99 균등 | 팬 판단의 습도 조건 |
| 쾌적 구간 15 % | 온도 22~29, 습도 60~65, 팬 33·66·100 | autoctl "한 단계 내림"이 나오는 좁은 구간 — 없으면 down 이 4 % 뿐 |
| 팬·LED 현재값 | 팬 0·33·66·100 (+ 20·50·80), LED 0~100 | autoctl 은 "지금 단계에서 한 칸"을 정한다 |
| 조도 | 30 % 경계(6,000·12,000), 나머지 = 실내광 + LED% × (15~130 lx/%) | 센서 위치에 따라 LED 효과가 크게 다름 |
| 토양·급수 | 수분 60 % 를 30·60 % 경계 근처, 급수 0~4 회(10 % 는 상한), 경과 분은 60·5·30 분 근처, 보정 상태 True 88 % · False 7 % · 모름 5 % | 급수 조건 조합 |
| 이상 15 % | 온도 고착 · 급수 후 무반응 · LED 높은데 조도 낮음 · 30 s 넘은 보고 · 온습도·조도 결측 · 토양 센서 오류 | `data_suspect` 학습 |
| 결측 3 % | 센서별 None | 결측 문장("missing") 학습 |

20,000 건(seed 20261127) 기준 train 정답 분포: fan_action hold 29 · up 27 · off 26 · down 18 % — 한쪽으로 쏠리지 않게 맞췄다.

seed 가 같으면 결과가 같다 → 회차별 비교가 공정하다. **seed 를 바꿔 늘리는 것**이 가장 싼 데이터 증강이다.

### 2-2. Influx 재생 (`replay.py`)

- 1분 평균 CSV 를 시각 순으로 읽으며 rules 엔진이 실시간으로 갖는 맥락을 다시 계산한다:
  하루 관수 횟수(펌프 0→양수 전환), 마지막 관수 경과, 관수 후 수분 변화(5~30 분 창), 30 분 추세, 30 분 고착, 데이터 나이(1분 해상도).
- **5 분마다 하나**만 쓴다(`subsample_min`) — 분 단위 행은 거의 같아 과적합만 키운다. 같은 state 문장은 한 번만.
- **날짜로 나눈다** — 마지막 10 % 날짜 = test, 그 앞 10 % = val. 같은 날이 train 과 test 에 같이 있으면 점수가 부풀려진다.
- 실데이터의 정답도 교사가 매긴다. 실데이터의 가치는 "현실의 값 분포·센서 습성"이다 — 예: 조명이 CUBE002 에 있던 10-06 에 LED 100 % 인데 CUBE001 조도 545 lx 였던 것은
  실제로 `led_high_lux_low`(센서 위치 문제)로 잡힌다.

### 2-3. 교사 라벨 (`labeler.py`) — 정답의 정의

**지금 서버에서 실제로 제어하는 api `autoctl` 의 판단**을 질문 단위로 옮긴 것(docs/05). 질문별 규칙표는 [04 §3](04_질문_특징_라벨_명세.md).
그래서 shadow 기간에 "모델 ↔ autoctl 일치율"을 바로 잴 수 있다.

**경계 근처는 부드러운 정답**: 값을 조금 흔들었을 때 답이 바뀌면 정답 0.7, 바뀐 답 0.3.

| 질문 | 흔드는 값 | 폭 |
|---|---|---|
| fan_action | 온도 · 습도 | ± 0.25 °C · ± 1 %p |
| light_action | 조도 | ± 150 lx |
| irrigate_now | 토양 | ± 0.5 %p |
| plant_stress | 온도 | ± 0.25 °C |

autoctl 은 "120 s 유지·앞 단계 적용 확인"으로 경계 떨림을 막는다. 상태가 없는 모델에게는 같은 효과를
"경계에서 확신을 낮추라"로 가르친다 → 보정이 쉬워지고, PolicyGate 가 낮은 확신을 기준 제어기로 돌린다.

## 4. ONNX·INT8

1. `export-onnx`: receptron/laya 의 `export/export_onnx.py <model_dir> <out_dir>` (opset 18, 동적 축 batch·seq·options).
   체크포인트 폴더에 `rl_common.py` 가 있어야 해서 키트가 기반 폴더에서 복사해 둔다.
2. `convert --precision int8`: onnxruntime `quantize_dynamic`(가중치 INT8) — fp32 약 1.7 GB → 약 0.45 GB 예상.
3. **같은 데이터로 fp32·INT8 둘 다 예측해 비교** — 질문별 최상위 답 일치율 ≥ 0.97. 미달이면 FP16(`--precision fp16`, 약 0.85 GB)을 쓴다.

## 5. 보정

- 모델(INT8)이 val 셋에 낸 확률 p 에 질문별 온도 T 를 적합: `p_T(i) ∝ p(i)^(1/T)`, 부드러운 정답에 대한 NLL 최소(황금분할, T ∈ [0.25, 8]).
- 이 변환은 로짓 온도와 수학적으로 같다(`calibration.py` 주석) → ONNX 를 건드리지 않고 묶음의 `calibration.yaml` 로만 적용.
- laya 내부 보정(`calib_frac`)과 별개다. 내부 보정은 PyTorch 원본 기준이고, 우리 것은 **실제로 배포하는 INT8** 기준이다.

## 6. 평가와 합격 기준

| 지표 | 정의 | 합격 |
|---|---|---|
| 정확도 | 보정 후 최대 확률 선택지 = 교사 최대 확률 선택지 | **≥ 0.90** (질문별) |
| ECE | 10 구간 | **≤ 0.10** |
| Brier | Σ(p − gold)² | 참고 |
| 혼동표 | 교사 → 모델 | 위험한 오답(예: severe → none, true → false 관수) 따로 확인 |
| fp32↔INT8 일치 | 최상위 답 | ≥ 0.97 |
| 젯슨 지연 | 5 문항 묶음 p95 | < 8 s (manual/03) |

불합격 질문도 묶음에는 들어간다 — 젯슨 rules 가 manifest 의 질문별 점수를 보고 그 질문을 **shadow 로만** 쓴다.
"합격" 은 모델이 제어에 쓰일 자격이고, 제어 자체는 PolicyGate·안전 봉투를 또 지나야 한다.

## 7. 실험 기록 규칙

- revision 이름: `YYYY-MM-DD_rN` (예: `2026-12-05_r1`). 한 번 쓴 이름은 다시 쓰지 않는다.
- `runs/<rev>/` 를 지우지 않는다(큰 파일은 git 밖). `train_info.json`·`compare.json`·`eval_report.json` 은 묶음 manifest 와 함께 남는다.
- 질문·특징을 바꾸면: `configs/questions.yaml` 수정 또는 `FEATURE_VERSION` 올림 → 데이터셋부터 다시.
- 비교 실험은 한 번에 하나만 바꾼다(seed·loss·데이터량).
