# 00. 프로젝트 개요 — 헬피아이 결정 모델 (jev)

작성 2026-11-27. 헬피아이(스마트 큐브 장미 재배) 파이널 프로젝트의 하위 과제.

---

## 1. 한 줄 요약

**젯슨 InfluxDB 의 센서 이력을 판정 문장으로 바꿔, 오픈 결정 모델 Laya 를 우리 장미 재배 판단에 맞게 미세조정하고,
젯슨 Xavier NX 에서 추론만 시켜 규칙 엔진(rules v2) 옆에서 "두 번째 판단"을 내게 한다.**

## 2. 왜 하는가

| 지금(rules v2) | 한계 | 결정 모델이 더하는 것 |
|---|---|---|
| 인터뷰 기반 규칙 7개, 우선순위 조정 | 규칙끼리 조합이 늘면 관리가 어렵다. 센서가 이상한 값을 내도 규칙은 그대로 믿는다 | 여러 신호를 한 번에 보고 **확률이 붙은** 판단. 센서 이상(`data_suspect`)처럼 규칙으로 쓰기 어려운 판단 |
| 판단 근거 = 규칙 이름 | "얼마나 확실한가"가 없다 | 질문별 확률 → 확신이 낮으면 규칙으로 물러서는 정책(PolicyGate) |
| 서버(젯슨) 중앙 제어 | — | 같은 젯슨 안에서 추론 → 인터넷 없이 동작 |

멘토 의견(2026-10-13)과의 연결: "최종 성능 지표", "이상치 알림 기준"이 필요하다 → 질문별 정확도·ECE(보정 오차)·범위 안 시간 비율을
지표로 쓰고, `data_suspect`·`plant_stress` 가 이상치 알림 기준이 된다.

## 3. 용어

| 용어 | 뜻 |
|---|---|
| **결정 모델** | 글을 쓰지 않고, 미리 정한 질문에 타입이 정해진 답(선택지·예/아니오·점수)과 확률만 돌려주는 모델 |
| **Jev** | TypeSafe AI 의 결정 모델(호스팅 전용, 비공개 가중치) |
| **Laya** | Convai Innovations 의 Jev 호환 **오픈 웨이트** 결정 모델(Apache 2.0). 이 프로젝트가 쓰는 모델 |
| **state** | 모델에 넘기는 현재 상황. 우리는 숫자를 직접 넘기지 않고 `features.py` 가 만든 짧은 영어 판정 문장을 넘긴다 |
| **질문(question)** | `fan_action`·`light_action`·`irrigate_now`·`plant_stress`·`data_suspect` 다섯 개 (`configs/questions.yaml`) |
| **교사(teacher) 라벨** | 지금 서버에서 실제로 제어하는 api **autoctl** 규칙으로 코드가 매긴 정답 확률(gold). 학습 데이터의 정답 (docs/05) |
| **보정(calibration)** | 모델이 말하는 확률이 실제 정답률과 맞도록 질문별 온도를 다시 맞추는 것 |
| **ECE** | Expected Calibration Error. 확률과 실제 정답률의 차이. 작을수록 좋다(목표 ≤ 0.1) |
| **묶음(bundle)** | 젯슨에 올리는 한 덩어리: ONNX 모델 + 토크나이저 + 보정값 + 질문 정의 + manifest + SHA256SUMS |
| **laya-edge** | 젯슨에서 묶음을 적재해 `POST /v1/systemone` 을 여는 Node 서버(`edge/`) |
| **shadow / advisory / primary** | 모델 답을 기록만 / 한 단계 차이까지 채택 / 그대로 채택 |

## 4. 범위

저장소 [Lumiela/helpai](https://github.com/Lumiela/helpai) 는 기능마다 브랜치를 나눈다. 이 과제는 **`decision_model` 브랜치**다.

| 포함 (`decision_model` 브랜치) | 제외 (다른 브랜치·폴더) |
|---|---|
| 특징 문장·질문·교사 라벨·합성 데이터 생성 | ESP32 펌웨어 — `Hardware` 브랜치 |
| InfluxDB 이력 내보내기·재생 | 서버 api·InfluxDB·nginx — `backend` 브랜치 (**수정하지 않는다**) |
| 미세조정·ONNX 변환·INT8·보정·평가 | 규칙 엔진 rules v2 — 아직 저장소 밖(로컬 `rule - based v2`). PolicyGate 연결은 다음 단계 |
| 묶음 만들기·검사, 젯슨 추론 서버 | 잎 병해·생장 단계·키 비전 — `Rose_Disease`·`Rose_Growth`·`Height`·`Crop_image_processing` |
| 문서·매뉴얼·시험 | AI 리포트·작물 모니터 그래프 — `langgraph` |

## 5. 구성 한눈에

```
 [서버: 네이버 클라우드 smartcubens.duckdns.org — backend 브랜치, 수정 없음]
  ESP32 ─8443─▶ mosquitto ⇄ api ──▶ InfluxDB ──▶ nginx /influx/ (조회 전용 창구)
                              ▲  ▲                         │            │
           POST control(인증)  │  │ GET values              │ Flux       │ Flux (읽기 토큰)
 [현장: 젯슨 Xavier NX 8 GB]    │  │                         ▼            ▼
  rules v2 ───────────────────┘──┘◀── InfluxReader     [집 PC RTX 5060 Ti 16 GB — 학습]
     │ PolicyGate                                       export-influx → replay + synth → 교사 라벨
     └─HTTP─▶ laya-edge (ONNX INT8, CPU)                → train(laya) → ONNX → INT8 → 예측·보정·평가
                  ▲                                     → bundle
                  └──────────── bundles/<rev>.tar ◀──(scp/USB)──┘
```

## 8. 알려진 위험

1. **Laya 기본판은 영샷 성능이 낮다**(공개 시험 0.36) → 미세조정이 전제. 1회차는 합성 데이터 위주라 "규칙 흉내"에 가깝다.
2. **laya 학습 API 가 판마다 바뀐다** — `laya_tools.py` 가 실행 시 이름을 확인하고, `check-env` 가 실제 이름을 보여 준다.
3. **ONNX 내보내기는 제3자 스크립트**(receptron/laya) — 미세조정 체크포인트에서 바로 되는지는 집에서 처음 확인한다.
4. **젯슨 CPU 지연** — 질문 5개 묶음이 8 초를 넘으면 주기를 늘리거나 경보 질문만 쓴다.
5. 교사 라벨은 서버 api **autoctl** 의 판단을 상태 없이 옮긴 것이다(120 s 유지·적용 확인 같은 실행 조건은 제어기 몫, 경계 근처는 부드러운 정답). autoctl 이 바뀌면 라벨도 바꿔야 한다 — docs/05, docs/04 §5.
