# 04. 질문·특징 문장·교사 라벨 명세 (autoctl 기준)

작성 2026-11-27 (v2 — 기준을 rules v2 에서 **서버 api 의 autoctl** 로 바꿈, docs/05).
기준 코드: `helpai_decide/features.py`(FEATURE_VERSION 2), `configs/questions.yaml`(version 2), `helpai_decide/labeler.py`,
작물표 `profiles/crops.json`(backend 브랜치 `api/app/crops.json` 복사본). **코드와 이 문서가 다르면 코드가 맞다.**

장미 값: 온도 22 ~ 30 °C · 습도 60 ~ 70 % (주야 같음) · 토양 30 ~ 60 % · 조도(주간) 6,000 ~ 12,000 lx · 주간 01:00 ~ 23:00 (KST).

## 1. Snapshot — 판단 입력 단위 (큐브 한 대)

| 필드 | 단위 | autoctl 에서 | 재생(replay)에서 |
|---|---|---|---|
| local_time | KST | 판단 시각 | CSV 시각 → KST |
| temperature · humidity · lux · soil_moisture | °C · % · lx · % | `temperature`·`humidity`·`lux`·`moisture_pct` | 1분 평균 |
| soil_calibrated | True / False / None | status `air`·`water` 가 공장 기본값(22520·11100)이면 False, 모르면 None | status 열의 마지막 값 |
| soil_sensor_ok | bool | `ads1115_ok` | 같은 열 (없으면 True) |
| led_pct · fan_pct · pump_on | % · % · bool | `led1`·`fan1`·`pump` 보고값 | 1분 평균 (펌프 > 0 = 켜짐) |
| irrigations_today | 회 | `pump_count` (KST 날짜) | 펌프 0→양수 전환 수 |
| minutes_since_irrigation | 분 | `now − pump_last_at` | 같음 (오늘 없으면 None) |
| moisture_change_since_irrigation | %p | — (확장) | 급수 직전 대비, 30 분 안 |
| temp_trend_30m · humidity_trend_30m | °C · %p | — (확장) | 30 분 창 처음 대비 |
| temp_flat_30m | bool | — (확장) | 30 분 범위 < 0.05 °C (10 개 이상) |
| max_data_age_s | 초 | `values_age` | 마지막으로 값이 들어온 분과의 차 |

## 2. state 문장 (9 키, 순서 고정)

| 키 | 문장 규칙 | 예 |
|---|---|---|
| crop | 작물 ID | `rose` |
| time | `HH:MM, daytime (light period 01:00 to 23:00)` / `HH:MM, night (light period …): lights must be off` | `14:10, daytime (light period 01:00 to 23:00)` |
| temperature | `T C; ` + 범위 문장(아래) + `; ` + 추세 (+ 고착 시 `value has not changed at all for 30 min`) | `31.2 C; above max 30.0 by 1.2; rising fast (+1.8 C in 30 min)` |
| humidity | `H %; ` + 범위 문장 + `; ` + 추세 | `66.0 %; within 60.0 to 70.0, close to max (within 5.0 %); flat over 30 min` |
| light | `LED n %` (+ `(already at max)` / `(off)`) + 주간: `; L lux, below min 6000 / above max 12000 / within 6000 to 12000` · `lux missing` · 야간: `lux target not used at night` | `LED 100 % (already at max); 4800 lux, below min 6000` |
| soil | `M %; below min 30.0 by d / above max 60.0 by d / within 30.0 to 60.0; sensor calibrated / sensor NOT calibrated (factory default) / calibration unknown` · 센서 오류 `sensor error (no valid reading)` | `28.0 %; below min 30.0 by 2.0; sensor calibrated` |
| irrigation | `k of 4 pulses used today` + `daily limit reached` + `none yet today` / `last m min ago, wait passed` / `… 60 min wait NOT passed` + (5~30 분) `moisture rose / did NOT rise after watering (±d)` + `pump running now` | `2 of 4 pulses used today; last 75 min ago, wait passed` |
| fan | `n % (level off/low/mid/high)` (+ `(already at max)` / `(already off)`) — 단계는 autoctl `nearest_step` | `33 % (level low)` |
| data | `fresh (last report s s ago)` / `STALE: last report s s ago` (> 30 s) | `fresh (last report 4 s ago)` |

**범위 문장** (온도: 폭 1.0 °C, 습도: 폭 5.0 %p — autoctl 의 "한 단계 내림" 조건):

| 조건 | 문장 |
|---|---|
| v < 최저 | `below min {lo} by {d}` |
| v > 최고 | `above max {hi} by {d}` |
| 최고 − 폭 < v ≤ 최고 | `within {lo} to {hi}, close to max (within {폭} C / %)` |
| 최저 ≤ v ≤ 최고 − 폭 | `within {lo} to {hi}, comfortably below max` |

**추세**: |변화| < 0.2 × 빠름 기준 → `flat over 30 min`, 그 이상 `rising/falling (±x unit in 30 min)`, 빠름 기준(온도 1.5 °C, 습도 8 %p) 이상 `rising fast`. 값 없음 → `trend unknown`.

## 3. 질문과 교사 라벨

### 3-1. fan_action (choice: off · down · hold · up)

autoctl 의 배기팬 판단을 "지금 단계에서 어떻게 바꿀지"로 묻는다. 위에서부터 처음 맞는 조건:

| 조건 (지금 단계 = 보고된 fan1 에 가장 가까운 0·33·66·100) | autoctl | 정답 |
|---|---|---|
| 온도 또는 습도 값 없음 | 유지 | hold |
| 온도 < 22 | 0 으로 | off (이미 0 이면 hold) |
| 온도 > 30 | 한 단계 올림 | up (이미 100 이면 hold) |
| 습도 > 70 | 한 단계 올림 | up (이미 100 이면 hold) |
| 습도 < 60 | 0 으로 | off (이미 0 이면 hold) |
| 지금 > 0 이고 온도 ≤ 29 이고 습도 ≤ 65 | 한 단계 내림 | down |
| 그 밖 | 그대로 | hold |

제어기 변환(`labeler.fan_target`): off → 0, down → 한 단계 아래, up → 한 단계 위, hold → 지금 단계.
부드러운 정답: 온도 ± 0.25 °C, 습도 ± 1 %p 흔들어 답이 바뀌면 0.7 / 0.3.

### 3-2. light_action (choice: off · decrease · hold · increase)

| 조건 | autoctl | 정답 |
|---|---|---|
| 야간 | 0 | off |
| 주간, 조도 없음 | 그대로 + 센서 점검 | hold |
| 주간, 조도 < 6,000 이고 LED < 100 | +10 % | increase |
| 주간, 조도 > 12,000 이고 LED > 0 | −10 % | decrease |
| 그 밖 | 그대로 | hold |

LED 보고값이 없으면 autoctl 처럼 50 % 로 본다. 주간 시작 50 % 와 "앞 단계 적용 확인"은 제어기 몫. 부드러운 정답: 조도 ± 150 lx.

### 3-3. irrigate_now (noul)

true 조건 (모두): 보정됨(True, 모름은 안 됨) · 토양 센서 정상 · 토양값 있음 · 토양 < 30 % · 펌프 꺼짐 · 오늘 < 4 회 · 마지막 급수 ≥ 60 분 전(또는 오늘 없음).
하루 종일 판단한다(야간 제한 없음). 부드러운 정답: 토양 ± 0.5 %p. 펄스 길이(5 s)·끄기는 제어기 몫.

### 3-4. plant_stress (choice: none · mild · moderate · severe) — 확장, 가장 나쁜 항목

| 단계 | 조건 |
|---|---|
| severe | 온도가 범위 밖으로 3 °C 넘게 (> 33 또는 < 19) |
| moderate | 온도가 범위 밖 · 토양 < 30 % 인데 오늘 4 회 다 씀(보정된 센서) |
| mild | 습도 범위 밖 · 토양 > 60 %(과습, 보정된 센서) · 주간 조도가 범위 밖인데 LED 가 이미 끝(100 % 또는 0 %) |
| none | 그 밖 |

autoctl 의 범위 이탈(excursion) 기록을 단계로 만든 것이다. 장미 습도 범위(60~70 %)가 좁아 실측(47 % 대)에서는 mild 가 흔할 것이다.

### 3-5. data_suspect (noul) — 하나라도 해당하면 true

| 이유 | 조건 | 출처 |
|---|---|---|
| stale | 마지막 보고 > 30 s | autoctl "보고가 30초 넘게 없음" |
| missing_temp_humidity | 온도 또는 습도 없음 | autoctl "온습도 값 없음" |
| missing_lux | 주간인데 조도 없음 | autoctl "조도 값 없음" |
| soil_sensor | `ads1115_ok = false` 또는 토양 없음 | autoctl "토양 값 없음" |
| stuck_temperature | 30 분간 온도 변화 < 0.05 °C | 확장 |
| no_rise_after_watering | 급수 후 5~30 분인데 수분 상승 < 1 %p | 확장 |
| led_high_lux_low | LED ≥ 80 % 인데 조도 < 1,000 lx | 확장 (조도계가 조명 아래가 아님 — 10-06 실측 545 lx 사례) |

## 5. 바꿀 때 규칙

1. 서버 autoctl·crops.json 이 바뀌면 → `profiles/crops.json` 복사, `features.py` 상수·`labeler.py` 규칙을 맞추고 시험부터 고친다.
2. 문장 규칙을 바꾸면 `FEATURE_VERSION` + 1. 질문을 바꾸면 `questions.yaml` 의 `version` + 1 (해시는 자동으로 바뀐다).
3. 무엇이든 바꾸면 **데이터셋부터 다시** 만들고 재학습한다. 이전 묶음은 젯슨에서 자동으로 shadow 가 된다.
