## 2. state 문장 (9 키, 순서 고정)

| 키 | 문장 규칙 | 예 |
|---|---|---|
| crop | 고정 `rose` | `rose` |
| time | `HH:MM, ` + 낮 `daytime (light period 06:00 to 22:00)` / 겨울 `winter month: lights allowed all day` / 밤 `night: lights must be off`. 매시 0~4 분이면 `; scheduled ventilation window now` | `14:10, daytime (light period 06:00 to 22:00)` |
| temperature | `T C; ` + 구간 + `; ` + 추세(+ 고착 시 `value has not changed at all for 30 min`) | `31.2 C; hot: above max 30.0 by 1.2; rising fast (+1.8 C in 30 min)` |
| humidity | `H %; ` + `high: at or above max 85.0` / `low: below 40.0 (no humidifier)` / `within range (max 85.0)` + 추세 | `71.0 %; within range (max 85.0); flat over 30 min` |
| light | `LED n %` (+ `(already at max)` / `(off)`) `; L lux, ` + `below min 6000` / `above max 12000` / `within 6000 to 12000` / `lux missing` | `LED 100 % (already at max); 4800 lux, below min 6000` |
| soil | `M %; below min 40.0 by d` / `at or above min 40.0` + `; sensor calibrated` / `sensor NOT calibrated` | `38.0 %; below min 40.0 by 2.0; sensor calibrated` |
| irrigation | `k of 12 used today` + `daily limit reached` + `none yet today` / `last m min ago, interval passed` / `… interval 20 min NOT passed` + (5~30 분이면) `moisture rose/did NOT rise after watering (±d)` + `pump running now` | `3 of 12 used today; last 45 min ago, interval passed` |
| fan | `n % (level off/low/mid/high)` | `33 % (level low)` |
| data | `fresh (oldest reading s s old)` / `STALE: oldest reading s s old` (> 60 s) | `fresh (oldest reading 4 s old)` |

**온도 구간** (팬 단계가 바뀌는 온도를 프로필에서 계산):

| 구간 | 조건 (rose.yaml) | 문장 |
|---|---|---|
| critical | T ≥ 35 | `critical: at or above 35.0 by d` |
| hot | 30 ≤ T < 35 | `hot: above max 30.0 by d` |
| very_warm | 29.15 ≤ T < 30 | `very warm (29.1 to max 30.0)` |
| warm | 27.475 ≤ T < 29.15 | `warm (27.5 to 29.1)` |
| slightly_warm | 26 ≤ T < 27.475 | `slightly warm (26.0 to 27.5)` |
| comfortable | 22 ≤ T < 26 | `comfortable (22.0 to 26.0)` |
| cold | T < 22 | `cold: below min 22.0 by d` |

27.475·29.15 는 v2 의 비례 환기(26 °C → 20 %, 30 °C → 100 %)에서 팬 값이 49.5 %(low↔mid)·83 %(mid↔high)가 되는 온도다.

**추세 문장**: |변화| < 0.2 × 빠름 기준 → `flat over 30 min`, 그 이상 `rising/falling (±x unit in 30 min)`,
빠름 기준(온도 1.5 °C, 습도 8 %p) 이상이면 `rising fast`. 값 없음 → `trend unknown`.

## 3. 질문과 교사 라벨

### 3-1. fan_level (choice: off · low · mid · high → 0 · 33 · 66 · 100 %)

| 순서 | 조건 | 정답 |
|---|---|---|
| 1 | T ≥ 35 | high |
| 2 | T < 22 | off (22 − 0.25 안은 off 0.7 / low 0.3) |
| 3 | 그 밖: 기본값 = T ≥ 30 → 100, 아니면 26~30 °C 를 20~100 % 로 비례 (T 없음 → 지금 팬 값) | |
| 4 | 바닥값: 습도 ≥ 85 → 60 %, 환기 창(매시 0~4 분) → 50 % | 기본값과 큰 쪽 |
| 5 | 값 → 가장 가까운 단계 (< 16.5 off, < 49.5 low, < 83 mid, 그 이상 high) | |
| 6 | 온도가 결정했고 단계 경계(27.475·29.15·22) ± 0.25 °C 안 | 정답 0.7 / 이웃 단계 0.3 |

### 3-2. light_action (choice: off · decrease · hold · increase)

| 순서 | 조건 | 정답 |
|---|---|---|
| 1 | T ≥ 35 | LED > 30 이면 decrease, 아니면 hold |
| 2 | T < 22 (LED 보온 사용) | LED < 100 이면 increase, 아니면 hold — **밤에도** |
| 3 | 밤(조명 허용 시간 밖) | off |
| 4 | 조도 없음 | LED < 100 이면 increase, 아니면 hold |
| 5 | 조도 < 6,000 | LED < 100 이면 increase(6,000 − 150 안은 0.7/hold 0.3), 아니면 hold |
| 6 | 조도 > 12,000 | LED > 0 이면 decrease(+150 안은 0.7/hold 0.3), 아니면 hold |
| 7 | 범위 안 | hold (경계 150 lx 안은 hold 0.7 / 움직일 쪽 0.3) |

### 3-3. irrigate_now (noul)

true 조건 (모두): 토양값 있음 · 토양 < 40 % · 보정됨 · 오늘 < 12 회 · 마지막 관수 ≥ 20 분 전(또는 오늘 없음) · 지금 펌프 꺼짐.
조건이 다 맞을 때 토양이 40 ± 1 %p 안이면 0.7/0.3.

### 3-4. plant_stress (choice: none · mild · moderate · severe) — 가장 나쁜 항목

| 단계 | 조건 |
|---|---|
| severe | T ≥ 35, 또는 T ≥ 33(최고 + 3), 또는 T < 19(최저 − 3) |
| moderate | T ≥ 30 또는 T < 22 · 토양 < 40 % 인데 오늘 관수 상한 도달(보정된 센서) |
| mild | 습도 ≥ 85 또는 < 40 · 낮에 조도 < 6,000 인데 LED 이미 100 % |
| none | 그 밖 |

### 3-5. data_suspect (noul) — 하나라도 해당하면 true

| 이유 코드 | 조건 |
|---|---|
| stale | 가장 오래된 데이터 > 60 s |
| stuck_temperature | 30 분간 온도 변화 < 0.05 °C |
| missing_reading | 온도 또는 습도 없음 |
| no_rise_after_watering | 관수 후 5~30 분 사이인데 수분 상승 < 1 %p |
| led_high_lux_low | LED ≥ 80 % 인데 조도 < 1,000 lx |

## 4. rules v2 와 다른 점 (의도한 차이)

| 항목 | rules v2 | 교사 | 이유 |
|---|---|---|---|
| 저온 팬 | 상한 20 %(idle 그대로) | off | api autoctl(저온 → 0)·질문 문구와 맞춤 |
| 히스테리시스 | latch (상태) | 경계 근처 부드러운 정답 | 모델은 상태가 없다 |
| 주기 환기 | epoch 분 기준 | 현지 분 기준 | KST 는 정시 오프셋이라 같다 |
| 팬 값 | 연속 0~100 | 4 단계 | api autoctl 단계와 같고, 선택지가 적을수록 Laya 가 정확 |
| 조명 증감 폭 | step 10 %(프로필) · 엔진 max_step 20 | 방향만(increase/decrease) | 폭은 코드(PolicyGate)가 정한다 |
| plant_stress·data_suspect | 없음(경보 일부만) | 새 판단 | 멘토 의견 "이상치 알림 기준" |

## 5. 바꿀 때 규칙

1. 문장 규칙(`features.py`)을 바꾸면 `FEATURE_VERSION` + 1.
2. 질문(`questions.yaml`)을 바꾸면 해시가 바뀐다 — `version` 도 올린다.
3. 교사(`labeler.py`)를 바꾸면 시험(`tests/test_core.py`)부터 고친다.
4. 셋 중 무엇이든 바꾸면 **데이터셋부터 다시** 만들고 재학습한다. 이전 묶음은 젯슨에서 자동으로 shadow 가 된다.
