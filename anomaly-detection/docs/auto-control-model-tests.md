# 자동 제어 모델 시험 — Laya · Chronos-2

> 작성: 랩탑 ClaudeCode (Claude Opus 5.5). 시험: 2026-11-25 ~ 11-26.
> 팀 내부 작업일지(자동제어모델 작업일지 1~3절)를 외부 공유용으로 정리한 문서다. 수치는 작업일지와 같다.
> 시험 코드·문제·결과는 [`../laya-test/`](../laya-test/) 와 [`../chronos-test/`](../chronos-test/) 에 있다.

## 1. 배경

- 스마트큐브의 자동 제어는 지금 **규칙 기반**이다. 네이버 클라우드 서버의 api 가 10초마다 작물별 허용 범위와 센서 값을 비교해 배기팬·펌프·LED 를 제어한다. 시험 당시(2026-11-25) 자동 제어가 켜진 큐브는 0대였다.
- 이 범위 판정과 설비 가동·정지를 로컬 의사결정 모델 **Laya** 에 맡길 수 있는지 랩탑에서 시험했다.
- 이어서 온습도를 미리 내다보는 예측 모델 **Chronos-2** 를 시험했다.

## 2. Laya 개요 (제작사 자료)

| 항목 | 내용 |
|---|---|
| 제작·라이선스 | Convai Innovations, Apache 2.0 |
| 하는 일 | 글을 쓰지 않고, 정해 준 질문에 선택(choice)·점수(score)·예/아니오(noul)로 확률과 함께 답한다. 호출할 때만 답하며 스스로 감시하지 않는다 |
| 영어판 | 매개변수 421M, 입력 512토큰 |
| 튜닝판(typed-decisions) | 영어판을 에이전트 실행 기록 관찰·고객 응대·송장 처리·보안 사고의 네 업무 1,200건(판단 6,000개)으로 학습 |
| 튜닝 없는 정확도 | 0.362(무작위 0.318, 가장 흔한 답만 고를 때 0.461). 튜닝판 0.766 |
| 설치 조건(PyPI) | Python 3.10 이상. 0.4.31 은 함께 설치하는 vegaml 때문에 torch 2.4 이상·transformers 5.17 이상 |
| 문서에 없는 것 | 숫자 비교·시계열 성능, IoT·설비 제어, Jetson·ARM 설치 |

- 젯슨(L4T R35.6.5)에는 Python 3.8·3.9 만 있어 그대로는 설치할 수 없다.

## 3. Laya 시험

### 3.1 환경

| 항목 | 값 |
|---|---|
| 기기 | 랩탑, NVIDIA GTX 1650 Ti 4 GB. float32 |
| 실행 환경 | Python 3.12.13, torch 2.14.1+cu126, transformers 5.22.2, laya 0.4.31 |
| 모델 | `convaiinnovations/laya`(영어판, revision `fd4f9dbc…`), `convaiinnovations/laya-typed-decisions`(튜닝판, revision `3903ff99…`). 받은 뒤 오프라인 실행 |

### 3.2 시험 문제

- 센서 기록: CUBE001 10분 간격 값(2026-09-26 ~ 11-25), [`../laya-test/cube001_10min.csv`](../laya-test/cube001_10min.csv).
- 정답: 작물 rose 의 주간 범위(온도 22~30 ℃, 습도 60~70 %, 토양 수분 30~60 %, 조도 6,000~12,000 lx). 경계값과 같으면 범위 안. 배기팬 정답은 실제 규칙 함수 `autoctl.evaluate()` 의 결과(배기팬 33 %, 낮 12시).

| 묶음 | 미만 | 범위 안 | 초과 | 합 |
|---|---|---|---|---|
| 실제 기록 | 309 | 235 | 111 | 655 |
| 합성(경계 근처 포함) | 160 | 160 | 160 | 480 |
| 합 | 469 | 395 | 271 | 1,135 |

- 1,135개 중 **서로 다른 입력(항목·값)은 592개**다. 실제 기록에서 같은 값이 여러 번 뽑혔다.
- 배기팬 문제 300개(내림·유지·올림 각 100). 서로 다른 입력은 295개.

### 3.3 결과 — 범위 판정

값과 허용 범위를 주고 미만·범위 안·초과를 물었다.

| 묻는 방식 | 영어판 (1,135개) | 튜닝판 (1,135개) | 영어판 (중복 제거 592개) | 튜닝판 (중복 제거 592개) |
|---|---|---|---|---|
| JSON, 세 가지 중 선택 | 0.346 | 0.427 | 0.280 | 0.399 |
| JSON, 선택지 순서만 반대 | 0.411 | 0.419 | 0.375 | 0.378 |
| JSON, 예/아니오 두 질문 | 0.352 | 0.404 | 0.338 | 0.372 |
| 문장, 세 가지 중 선택 | 0.419 | 0.351 | 0.348 | 0.294 |
| 문장, 예/아니오 두 질문 | 0.346 | 0.362 | 0.291 | 0.297 |
| 가장 흔한 답(미만)만 고를 때 | 0.413 | 0.413 | 0.493 | 0.493 |

- 범위를 벗어난 740건(1,135개 기준) 중 "범위 안"으로 놓친 수: 영어판 509 ~ 686, 튜닝판 474 ~ 720.
- 튜닝판은 하한 미만 469건 중 가장 많이 맞힌 방식이 12건이었다.
- 선택지 순서만 뒤집었을 때 답이 바뀐 입력(592개 기준): 영어판 27.2 %, 튜닝판 9.6 %.
- 경계에서 범위 폭 이상 떨어진 값(151개)의 정확도: 영어판 JSON 선택 0.086, 문장 선택 0.013.
- 같은 입력에는 두 모델 모두 항상 같은 답을 냈다.

### 3.4 결과 — 배기팬 결정, 비교 결과를 문장으로 준 경우

| 시험 | 서로 다른 입력 | 영어판 | 튜닝판 |
|---|---|---|---|
| 배기팬, 숫자와 규칙 문구 제공(300개) | 295 | 0.370 | 0.333 (300개 모두 "올림") |
| 배기팬, 온도·습도 판정은 코드가 계산(300개) | 13 | 0.667 | 0.667 |
| 범위, "상한보다 높다" 같은 비교 결과 문장, 선택 | 12 | 1.000 | 1.000 |
| 범위, 같은 문장, 예/아니오 | 12 | 0.581 | 1.000 |

- "코드가 계산" 배기팬 문제 중 온도 초과·습도 미만 26개는 선택지 문구로는 "올림"과 "내림"에 모두 해당했다(규칙 정답 "올림"으로 채점). 이 26개를 빼면 두 모델 모두 0.635 다.
- 비교 결과 문장 시험의 문장은 선택지 문구와 거의 같다.

## 4. Chronos-2 온습도 예측 시험

### 4.1 환경

| 항목 | 값 |
|---|---|
| 패키지 | `chronos-forecasting` 2.3.2 (Apache 2.0) |
| 모델 | `amazon/chronos-2`, revision `29ec3766…`(약 478 MB). 받은 뒤 오프라인 실행 |
| 실행 환경 | Python 3.12.13, torch 2.14.1+cu126, transformers 5.22.2, pandas 3.1.1. GTX 1650 Ti, float32 |

### 4.2 방법

- 데이터: 3.2 와 같은 10분 간격 기록. 10분 격자 8,640칸으로 펴고 기록이 없는 칸은 빈 값(NaN)으로 넣었다(Chronos-2 는 빈 값 위치를 가리고 계산한다).
- 예측 시점: 30분마다, 지금 온도·습도 값이 있고 직전 12시간 중 6시간 이상 기록이 있는 시점 795개(2026-09-30 15:00 ~ 11-19 09:00 KST, 날짜 24개).
- 각 예측은 직전 최대 85시간(512칸)을 보고 3시간(18칸)을 예측한다. 0.1·0.5·0.9 분위수를 받고 중앙값을 예측값으로 썼다.

| 이름 | 내용 |
|---|---|
| 기준선 | 지금 값이 그대로 간다고 봄 |
| 따로 | Chronos-2, 온도·습도 각각 |
| 함께 | Chronos-2, 온도·습도를 함께 + 과거 배기팬·LED·조도 |
| 설비 계획 포함 | "함께" + 앞으로 3시간의 배기팬·LED 실제 기록 |

- 신뢰 구간: 날짜 단위 부트스트랩 2,000번. 비율 = 모델의 평균 절대 오차 ÷ 기준선의 평균 절대 오차.

### 4.3 결과 — 평균 절대 오차

| 대상 | 기준선 | 따로 | 함께 | 설비 계획 포함 | 함께 ÷ 기준선 95 % 구간 |
|---|---|---|---|---|---|
| 온도 30분 뒤 | 0.313 ℃ | 0.290 | 0.285 | 0.251 | 0.86 ~ 0.96 |
| 온도 60분 뒤 | 0.501 ℃ | 0.433 | 0.420 | 0.355 | 0.78 ~ 0.89 |
| 온도 3시간 뒤 | 0.971 ℃ | 0.759 | 0.725 | 0.632 | 0.69 ~ 0.82 |
| 습도 30분 뒤 | 0.914 %p | 0.905 | 0.881 | 0.834 | 0.92 ~ 1.01 |
| 습도 60분 뒤 | 1.324 %p | 1.251 | 1.215 | 1.116 | 0.87 ~ 0.96 |
| 습도 3시간 뒤 | 2.624 %p | 2.469 | 2.449 | 2.320 | 0.85 ~ 1.00 |

- "지금 값 + 24시간 전 같은 구간의 변화량" 방법은 기준선보다 오차가 컸다(온도 60분 뒤 0.624 ℃, 같은 시점의 기준선 0.505 ℃).
- 80 % 예측 구간 안에 실제 값이 든 비율은 0.733 ~ 0.816 이다.
- 같은 입력으로 두 번 실행해 결과가 같았다.

### 4.4 결과 — 60분 안 범위 이탈 경보

지금 값이 범위 안인 시점에서 앞으로 60분 안에 범위를 벗어나는지 맞히게 했다. 기준선은 경보를 내지 않는다.

- 온도(22~30 ℃): 범위 안 515번, 실제 이탈 46번(하한 아래 44, 상한 위 2).
- 습도(60~70 %): 범위 안 126번, 실제 이탈 22번(하한 아래 14, 상한 위 8).

| 방법 | 경보 기준 | 온도 경보 | 그중 맞음 | 온도 놓침 | 습도 경보 | 그중 맞음 | 습도 놓침 |
|---|---|---|---|---|---|---|---|
| 함께 | 중앙값이 범위 밖 | 13 | 11 | 35 | 9 | 6 | 16 |
| 함께 | 0.1 또는 0.9 분위수가 범위 밖 | 73 | 27 | 19 | 63 | 19 | 3 |
| 설비 계획 포함 | 중앙값이 범위 밖 | 26 | 22 | 24 | 9 | 6 | 16 |
| 설비 계획 포함 | 0.1 또는 0.9 분위수가 범위 밖 | 68 | 34 | 12 | 60 | 19 | 3 |

### 4.5 속도·메모리

- GPU: 795건을 "따로" 6.0 ~ 6.2초, "함께" 19.0 ~ 19.4초. GPU 최대 936 MB.
- 랩탑 CPU(i7-10750H, 6스레드): 64건 묶음 2.63초(건당 41.0 ms), 1건 101.3 ms.

### 4.6 데이터에 대해 확인한 것

- 기록 기간의 LED 꺼짐 시각은 19:30·20:00·22:30 등으로 일정하지 않다. 배기팬 값이 바뀐 것은 18번이다.
- "설비 계획 포함"에 넣은 배기팬·LED 값은 실제로 기록된 값이다.
- LightGBM 등 다른 예측 모델, 서버 CPU 에서의 실행, CUBE001 외 큐브는 시험하지 않았다.

## 5. 파일

| 폴더 | 파일 |
|---|---|
| `laya-test/` | `build_cases.py`(문제 만들기) · `run_laya.py`·`run_laya2.py`(실행) · `score.py`·`score2.py`(채점) · `compare_unique.py`(중복 제거 비교) · `cases.json` · `cube001_10min.csv` · `results.json`(영어판) · `results_typed_decisions.json`(튜닝판) · `score.txt` · `score_typed_decisions.txt` · `compare_unique.txt` |
| `chronos-test/` | `run_chronos.py` · `analyze.py` · `chronos_results_run1.json`(첫 실행, CPU 측정 포함) · `chronos_results.json`(두 번째 실행) · `chronos_pred.npz`(예측 시점별 값) · `analyze.json` · `analyze.log` · `run_full.log` |

- `build_cases.py` 는 서버 api 코드(`edgeserver-JS/api`)의 규칙 함수를 불러온다. 그 폴더 위치는 환경 변수 `SMARTCUBE_API_DIR` 로 정한다.
- 실행 스크립트는 모델 폴더를 스크립트의 상위 폴더 `model/` 에서 찾는다. 모델 파일은 올리지 않았다.
